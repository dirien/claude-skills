# Lifecycle and governance

Who does what from "repo exists" to "published", and what happens on day 2.
The scripts and the other references say how; this page says who and when.
`AGENTS.md` ("Providers mirrored to pulumi-labs") holds the rules that bind
the other agents. If this page and `AGENTS.md` disagree, stop and report.

## Roles

| Who | Does | Never |
|---|---|---|
| Engin (human) | Decides the Registry name, creates and configures the repo (`repo-setup.md`), approves cards, makes the repo public/protected, tags, decides on `BREAKING` releases and 1.0 | |
| Architect | Builds and maintains `lib/providers/<p>`, adds `[Unreleased]` CHANGELOG entries | Edits `version.txt` or `carved-providers.json` of a mirrored provider, touches a mirror |
| Reviewer | Clears every PR on its exact head SHA: monorepo PRs and Publisher PRs in the mirrors | |
| Publisher | Identity switch, export, sync, release-cut PR, onboarding issues, feedback loop, publication check | Tags, creates or configures repos, edits a mirror by hand, bumps `version.txt` outside a release-cut PR |
| Pulumi engineering | Registry-side setup, tag `v0.x.y`, publish | |

## Card template (Autoregistry Publishing board)

One card per provider, reused for every release. The header is generated by
the Publisher when it creates the Backlog card; a human ticks the checklist.

```
Provider: <name> (<Display Name>)
Kind: native | bridged from <upstream>@<version>
Monorepo path: pulumi/autoregistry lib/providers/<name>
Target repo: pulumi-labs/pulumi-<name> (not created | created, empty | imported)
Go module: github.com/pulumi-labs/pulumi-<name>
Registry name: <name>: free | taken | decided
Labels: (only if the board cannot hold labels) needs-human, rework, update, breaking, name-taken, waiting-on-build

Approval checklist (a human completes this before moving the card to Approved):
- [ ] Registry name decided and checked free on the Pulumi Registry (a name cannot be undone)
- [ ] pulumi-labs/pulumi-<name> exists: PUBLIC and EMPTY (no README, license or .gitignore), created and
      configured with scripts/repo_setup.sh; `repo_setup.sh verify <name>` printed all PASS (link the output)
- [ ] The workprentice app covers the repo (all repositories, or the repo added) with Workflows permission
- [ ] Provider Readiness passed on current monorepo main: link the `Provider Readiness` workflow run for <name>
- [ ] Kind is supported by the skill (native today; bridged only when the skill says so)
- [ ] No open PR touches lib/providers/<name> except the Publisher's (the identity switch freezes it until it merges)
- [ ] Vendor name and trademark use cleared, if the vendor is not Pulumi-friendly by default
- [ ] Approved by: <human>, <date>

Provider that does not exist yet: a human may create the card before `lib/providers/<name>` exists. The Publisher
files a `provider-request` issue on `pulumi/autoregistry` (check for an existing one first; `needs-triage`, link the
card, card description as context), adds `waiting-on-build` to `Labels:`, keeps the card in Backlog and notifies Engin
(`normal`). When the directory appears on main, it removes `waiting-on-build`, completes the card from this template
and links the request issue. See `AGENTS.md` ("Provider requests").

Update approval (a breaking release of a published provider): a human adds "Approved: breaking v<x.y.z>" to the card.
```

The Publisher re-checks every line that a script can check (repo exists, empty,
public; readiness run link is green and recent) and moves the card back to
Approved with `needs-human` if one is untrue.

## Version and CHANGELOG discipline (mirrored providers)

- `lib/providers/<p>/version.txt` holds `0.x.y`. It exists for every mirrored
  provider (the identity-switch PR adds `0.1.0` when a provider has none, which
  is the case for every bridged provider today). `tools/provider-metadata`
  fails the build if it is missing, not `0.x.y`, or older than `lastSyncedVersion`.
- Developers add user-facing entries under `## [Unreleased]` in
  `lib/providers/<p>/CHANGELOG.md` in the same PR (the `Mirror Release Notes`
  check enforces it for shipped code; the label `impact/no-changelog-required`
  exempts Dependabot and tooling PRs). Prefixes: `BREAKING:` for a breaking
  change, `Security:` for a security fix.
- **Only the Publisher's release-cut PR bumps `version.txt`.** Nobody else does.

## Release cut (Publisher)

Per mirrored provider, at most one provider per run, in the lifecycle run:

1. Cut when the provider is Published or Handover with a synced mirror and
   `[Unreleased]` on monorepo `main` has at least one entry, and the last cut
   was 7 or more days ago. Cut sooner (next run) when an entry starts with
   `Security:`. With no entries, cut a patch at most monthly when
   `git log <lastSyncedCommit>..origin/main -- lib/providers/<p>/provider/go.mod`
   shows dependency changes (the entry is generated: "Updated dependencies").
2. Version math, 0.x only: any `BREAKING:` entry or a new resource/function
   (an "Added" entry) is a minor bump (`0.1.4` to `0.2.0`); anything else is a
   patch. Never `1.0.0`; moving to 1.0 is Engin's decision.
3. A `BREAKING:` entry: label the card `breaking`, notify Engin (`important`),
   and open no release-cut PR until he writes "go" on the card.
4. Branch `publisher/release-<p>-v<version>`; the PR changes exactly two files:
   `version.txt`, and `CHANGELOG.md` where the `[Unreleased]` entries move under
   `## [<version>] - <date>` (leave an empty `## [Unreleased]`). Branch, title
   and first body line are in "Publisher PR conventions" below. Reviewer
   clearance on the head SHA, green checks (including `Mirror Release Notes` and
   `Provider readiness`), squash-merge.
5. The merge makes `version.txt` greater than `lastSyncedVersion`: follow
   `sync.md` (same run if time allows, else next run).

Why the Publisher and not the Architect: the Architect's and Dependabot's PRs
are many, small and parallel, and none of them knows what else is unreleased;
per-PR bumps would conflict on `version.txt`, force a mirror sync and a tag per
change, and Dependabot cannot edit `version.txt` at all. One owner of version
math, batching weekly, keeps the mirror quiet, makes breaking changes visible
in one place and fits the Publisher's existing `breaking` escalation.

## Candidate sync (before the first tag, or any untagged version)

While `v<lastSyncedVersion>` does not exist as a tag in the mirror
(`git ls-remote --tags https://github.com/pulumi-labs/pulumi-<p> 'v<ver>'`),
fixes for engineering feedback reach the mirror by re-syncing the SAME version:
no `version.txt` bump, branch `sync/v<version>-<n>` (n = 2, 3, ...), commit
`Sync pulumi/autoregistry@<sha> (v<version>)`. Once the tag exists, the next
sync needs a new version (a release cut). Never move or re-create a tag.
A "ready to tag" notice names the mirror `main` SHA; a candidate sync after it
supersedes it and the Publisher sends a new notice.

## Publisher PR conventions

So the Reviewer can find them and a human can tell them apart:

| PR | Repo | Branch | Title prefix |
|---|---|---|---|
| Identity switch | monorepo | `publisher/identity-<p>` | `Identity switch for <p>` |
| Export record | monorepo | `publisher/export-<p>` | `Record export of <p>` |
| Release cut | monorepo | `publisher/release-<p>-v<ver>` | `Release <p> v<ver>` |
| Sync fields | monorepo | `publisher/synced-<p>-v<ver>` | `Record sync of <p> v<ver>` |
| Sync | mirror | `sync/v<ver>` (`-<n>` for a candidate re-sync) | `Sync pulumi/autoregistry@<sha> (v<ver>)` |

First line of every body: `Publisher PR: <kind> <p> head <40-char sha>`, updated
on every push. The Publisher requests clearance with a PR comment
`Clearance requested for <40-char sha>` (and `ask_agent` when its tools allow).
It merges only when a comment from the Reviewer says `CLEARED FOR MERGE` and names
that exact SHA, posted after the request. Reviewer and Publisher post as the same
GitHub identity, so read the body, not the review state.

## Mirror-side events

- **Dependabot or security-update PRs on a mirror**: repo setup turns security
  updates off and ships no `dependabot.yml`, so none should appear. If one does,
  never merge it. Comment "This repository is generated from a private source;
  the update is made there." and close it, then check the repo settings and tell
  Engin (`normal`). A Dependabot alert (not a PR) is routed to the monorepo:
  open an issue on `pulumi/autoregistry` titled `Mirror alert: <p> <advisory>` for
  the Architect; the fix ships through the next release cut (`Security:` entry).
- **External contributor PR or issue on a mirror**: reply once, politely and
  without internal detail: changes are made in the source repository and the
  maintainers will apply it. Open a monorepo issue titled `Mirror feedback: <p>
  <summary>` linking it (the Architect picks up GitHub issues); close the PR.
  Security reports arrive via private vulnerability reporting: human only,
  `urgent`.
- **A direct push or merge in the mirror by a human**: it is drift. Before every
  sync (and once per feedback run for each mirrored provider that has a mirror),
  run `python3 scripts/check.py --repo <mirror> --against-source <monorepo
  checkout>` on the mirror's `main` BEFORE exporting. Drift in the output: do not
  sync; notify Engin (`important`) with the paths; the change must be ported into
  the monorepo (monorepo issue for the Architect) or explicitly dropped by Engin.
  A sync overwrites the mirror, so an unported edit would vanish silently.
  The default-branch ruleset means a direct push needs an admin bypass; GitHub
  records it in the audit log.

## Breaking, removal, rename, upstream major, missing version.txt

- **Breaking change**: `BREAKING:` entry; the Publisher waits for Engin's go,
  then a minor bump. A breaking update of a published provider needs the card's
  "Approved: breaking" line.
- **Upstream Terraform major bump (bridged)**: treat as breaking unless the bump
  PR shows no schema diff; the PR author writes the `BREAKING:` entry.
- **Removing or renaming a mirrored provider in the monorepo**: not allowed for
  agents. The name is permanent in every registry. `provider-metadata` fails if
  `lib/providers/<p>` disappears while it is listed. To retire one, Engin archives
  the mirror and removes the entry in his own PR; a "rename" is a new provider,
  a new card and a new repo.
- **No `version.txt`**: the identity-switch PR adds `0.1.0`; the gate enforces it
  from then on.
- **Publication verified, then `listed`**: first publication only.
